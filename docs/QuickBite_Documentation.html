1 Project Synopsis

QuickBite is a comprehensive, microservices-based Food Delivery Platform built with Spring Boot on the backend and Angular on the frontend. The system allows customers to browse restaurants, add items to their cart, place orders, make payments securely via Razorpay, and track their delivery. It also features dedicated flows for Restaurant Owners to manage menus and Delivery Agents to complete handoffs.

The architecture consists of independently scalable microservices interconnected via an API Gateway. Each service manages its own MySQL database to ensure loose coupling. Inter-service data retrieval is handled synchronously, while asynchronous operations like notifications and delivery assignments are decoupled using RabbitMQ. Redis is heavily utilized for high-performance caching (menus, restaurants) and managing JWT token blacklists. All APIs are fully documented using Swagger/OpenAPI 3.0.

2 Detailed Requirements

2.1 Authentication & Authorization

  • User registration and login using JWT-based authentication.
  • Role-based access control (RBAC) supporting: CUSTOMER, OWNER, and DELIVERY_AGENT.
  • Token blacklisting mechanism implemented via Redis for secure logout.
  • Spring Security integration at the API Gateway to protect downstream routes.

2.2 Core Order Flow

  • Customers can browse cached restaurant menus and add items to a Cart.
  • Cart data is aggregated and validated by the Order Service upon checkout.
  • Orders are placed with an initial "PENDING" status.
  • Payment Service integrates with Razorpay to capture funds and generate receipts.

2.3 Delivery & Fulfillment

  • Restaurant Owners receive notifications to accept and prepare orders.
  • Delivery Agents are assigned orders based on availability.
  • Agents can update delivery status (e.g., OUT_FOR_DELIVERY, DELIVERED).
  • Asynchronous notifications dispatched to customers via RabbitMQ.

14 Database Schemas

Following the Database-per-Service pattern, QuickBite ensures isolation.

  • quickbite_auth: Stores users, roles, and hashed passwords.
  • quickbite_restaurant: Stores restaurant details, locations, and owner associations.
  • quickbite_menu: Stores items, descriptions, and pricing.
  • quickbite_order: Stores order headers, items, status, and total prices.
  • quickbite_payment: Stores transaction IDs and Razorpay references.
15 Non-Functional Requirements
  • Scalability: Services can scale independently based on load (e.g., scaling Order Service during peak hours).
  • Security: All inter-service calls use internal networking. External calls require a valid JWT issued by Auth Service.
  • Performance: Redis caching guarantees sub-100ms response times for browsing restaurants and menus.
  • Resilience: Services use Netflix Eureka for dynamic IP resolution, preventing hardcoded dependency failures.
16 Future Enhancements
  • Real-time Location Tracking: Integrate WebSockets/Google Maps API to track the delivery agent live.
  • AI Recommendations: Suggest food items based on past order history.
  • Push Notifications: Shift from standard in-app notifications to Firebase Cloud Messaging (FCM) for mobile devices.
  • Promotions Engine: Build a dedicated microservice for complex coupon logic and discounts.
